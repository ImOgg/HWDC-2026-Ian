# 設定與安全機制檢查方法

標準來源：docs/team-rules/security.md。根據本次 Spec／design、部署及身分邊界判斷適用規則。

- SEC-01／08：檢查原碼、受檢設定、錯誤回應與日誌；識別真實秘密、敏感資料及占位字串，回報位置而不複製秘密值。
- SEC-05／07：追查身分到用例及資料操作，確認物件／租戶授權、允許修改欄位與伺服器判定。不能只看到登入 attribute 就認定授權完整。
- SEC-06：確認認證方式、瀏覽器如何攜帶憑證及狀態變更入口，再檢查 CSRF；測試需同時覆蓋合法操作與拒絕情境。
- SEC-09：涉及密碼學、隨機數、XML、反序列化、上傳、資源使用或依賴風險時，核對實際使用的 API 與演算法，區分安全用途與一般識別用途（例如實體主鍵、追蹤 ID 使用 Guid 不屬安全用途）。沒有工具或最新漏洞資料時列明未驗證，不能聲稱已完成依賴掃描。
- SEC-10：檢查本次新增或修改的日誌呼叫，確認不可信值以訊息範本參數傳入，並追查值是否可能含 CR／LF。
- SEC-11／13：先確認部署邊界（HTTPS 或僅限本機 HTTP），再檢查 Cookie 屬性（含 antiforgery 與驗證 Cookie 的設定）、CORS 政策、HTTPS 重新導向與 HSTS 的中介軟體順序，以及對外連線與資料庫連線的加密設定。
- SEC-12：找出本次以使用者輸入呼叫 Regex 的位置，包括 new Regex、Regex 靜態方法、GeneratedRegex 與驗證屬性，確認逾時或 NonBacktracking 設定。

部署邊界與未實作能力來自當次規格；若改變邊界，重新檢查風險。不得在通用 Skill 預寫某個案例的安全豁免。
