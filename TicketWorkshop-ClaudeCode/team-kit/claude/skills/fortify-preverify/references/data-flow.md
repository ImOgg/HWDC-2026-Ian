# 資料流審查方法

標準來源：docs/team-rules/security.md。先識別受影響的入口與敏感操作，再追查來源 → 轉換 → 驗證／授權 → 操作／輸出。

| 實際資料流 | 適用規則 | 檢查依據 |
|---|---|---|
| 不可信文字到 HTML／attribute／JavaScript | SEC-02 | 實際輸出上下文、編碼或清理策略、繞過編碼的路徑 |
| 輸入到 SQL | SEC-03、05 | 參數化、查詢內容及物件／租戶授權 |
| 輸入到檔案 | SEC-04、09 | 規範化路徑、目錄邊界、檔案類型／大小與權限 |
| 輸入到 URL／程序 | SEC-04 | 可控制的目的地、redirect、內部網路存取及 shell 拼接 |
| 輸入綁定到資料／狀態 | SEC-05、07 | 允許欄位、伺服器授權、擁有者與受控狀態 |
| 輸入到日誌 | SEC-10 | 訊息範本參數、CR／LF 處理、是否夾帶敏感資料（SEC-08） |
| 輸入到回應標頭／Cookie | SEC-11 | 驗證與 CR／LF 移除、Cookie 屬性 |
| 輸入作為正規表示式的比對對象或 pattern | SEC-12 | 比對逾時、NonBacktracking、pattern 來源 |
| 輸入到 XML 解析或反序列化 | SEC-09 | DTD 與外部實體設定、型別決定方式 |

閱讀真正的呼叫與資料轉換，不以關鍵字命中直接判定漏洞。追不到必要來源或邊界時要求補資訊；沒有該資料流時標示不適用。
以測試核對防護與拒絕情境，但測試全綠不代替資料流審查。
每個資料流同時依 [Fortify 分類對照](fortify-categories.md) 標出正式掃描可能使用的分類名稱。
