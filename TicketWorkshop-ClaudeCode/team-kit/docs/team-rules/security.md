# 原碼安全規範

- **SEC-01 必要**：禁止將憑證、密碼、auth key、token 或私鑰寫入原碼、提交的設定或日誌；使用環境與平台支援的秘密管理。占位字串不等於真實洩漏，但範例不得鼓勵硬編碼。
- **SEC-02 必要**：不可信輸入先驗證，輸出依 HTML、attribute、JavaScript、URL 等實際上下文編碼；禁止未經明確清理策略的原始 HTML 輸出。
- **SEC-03 必要（涉及資料庫時）**：使用參數化操作，禁止將不可信值拼接成 SQL。查詢參數化不能代替物件存取授權。
- **SEC-04 必要（涉及檔案／URL／程序時）**：控制允許的路徑與目的地，防止越界存取、SSRF、open redirect 及命令注入；不得使用不可信字串組合 shell 命令。
- **SEC-05 必要**：依 Spec／design 的使用者、權限與部署邊界驗證操作及物件存取；涉及租戶時驗證租戶隔離。未交代必要的存取邊界時先釐清，不能自行假定所有人可操作。
- **SEC-06 必要（瀏覽器自動攜帶 cookie 的狀態變更時）**：使用適當的 CSRF 防護，MVC 表單採 antiforgery；GET 不改變業務狀態。其他認證方式按實際威脅模型判斷，不把所有 API 當 cookie 表單。
- **SEC-07 必要**：僅綁定允許修改的輸入欄位；權限、擁有者與受控狀態由伺服器判定，禁止直接綁定 entity 造成 overposting。
- **SEC-08 必要**：錯誤回應不洩漏 stack trace、連線字串、內部路徑或秘密；日誌與監控只保留必要且經處理的敏感資料。
- **SEC-09 必要（涉及時）**：密碼學與隨機數使用受支持的標準函式庫並選用安全演算法。安全用途的隨機值（token、重設碼、金鑰）使用 RandomNumberGenerator，不用 System.Random 或 Guid；安全用途的雜湊不用 MD5、SHA1，密碼使用專用雜湊器；對稱加密不用 DES、TripleDES、RC2、ECB 模式或固定 IV。XML 解析停用 DTD 與外部實體；反序列化不使用 BinaryFormatter，也不依輸入決定型別。上傳檔案及資源使用依實際用途限制型別、大小與處理成本。
- **SEC-10 必要（涉及日誌時）**：不可信輸入寫入日誌時使用訊息範本參數，不以字串串接或插值組訊息；可能含換行的值先移除或編碼 CR、LF 等控制字元，避免偽造日誌紀錄。
- **SEC-11 必要（設定 Cookie、回應標頭或 CORS 時）**：Cookie 設定 HttpOnly 與適當 SameSite，敏感 Cookie 不持久化；部署邊界使用 HTTPS 時設定 Secure。不可信輸入寫入回應標頭或 Cookie 前先驗證並移除 CR、LF。CORS 只允許明確列出的來源，不使用萬用字元或一律允許的判斷。
- **SEC-12 必要（以正規表示式處理不可信輸入時）**：設定比對逾時或使用 RegexOptions.NonBacktracking，避免回溯造成阻斷服務；不以不可信輸入作為 pattern。
- **SEC-13 必要（依部署邊界）**：部署環境使用 HTTPS，HTTPS 重新導向與 HSTS 依官方中介軟體順序設定；對外呼叫與資料庫連線使用加密傳輸。Spec／design 明定僅限本機 HTTP 練習時，SEC-13 與 SEC-11 的 Secure 要求列為不適用，並在審查 Limitations 註明正式部署前需補上。
