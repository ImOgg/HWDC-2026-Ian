# 測試與驗證規範

- **TEST-01 必要**：將本次 Spec 的接受情境對照實際測試與 assertion；涵蓋成功、拒絕、邊界及受影響的既有行為。測試名稱及數量不能代替證據。
- **TEST-02 必要**：Domain 規則用單元測試直接驗證；Application 用例測流程與介面互動，必要時使用替身；Web／Infrastructure 的整合行為使用適當整合測試。測試選擇依變更責任，不要求每次修改都重建所有層。
- **TEST-03 必要**：修復缺陷時加入能重現原問題的回歸測試。重構須保留既有外部行為的測試證據；新需求的具體期望由 Spec 定義。
- **TEST-04 必要**：測試可重複、隔離，不依賴執行順序、共享前次資料或未控制的外部服務。測試應有實質 assertion，禁止空白範本測試。
- **TEST-05 必要（涉及安全機制時）**：測試真實保護機制及正常／拒絕路徑；不得停用授權、驗證、編碼等機制來讓測試通過。
- **TEST-06 必要**：依 docs/project-context.md 直接執行 build/test，讀當次輸出與 TRX；失敗、零測試、未執行或略過不能當交付 PASS。
- **TEST-07 必要**：禁止刪除、跳過或弱化測試來消除 FAIL。若接受條件確實改變，先重新確認 Spec，再同步修改測試並說明原因。

dotnet 的執行結果確認程式能編譯、測試有執行且通過；Code Review 確認測試是否真的驗證需求。全綠不表示接受條件已完整涵蓋。
