# 程式品質規範

- **CODE-01 必要**：變更限於核准任務；保持既有公開契約及行為，除非 Spec 明確核准改變。依既有專案風格實作，不順便加入無關框架或大幅重構。
- **CODE-02 必要（涉及 I/O 時）**：採適當非同步 API，禁止以 .Result／.Wait 阻塞請求流程。用例與外部 I/O 在有取消需求時傳遞 CancellationToken，不將取消當正常成功。
- **CODE-03 必要**：區分預期業務拒絕與非預期系統失敗；結果契約清楚，禁止 catch 後吞掉例外、假成功或遺失原始例外資訊。重拋保留 stack trace。
- **CODE-04 必要**：正確處理 nullable、邊界與資源生命週期；IDisposable／IAsyncDisposable 按擁有權釋放。禁止不明生命週期的可變 static 狀態。
- **CODE-05 必要（共享狀態時）**：明確處理 thread safety 與一致性；不得只因單人測試成功就假設共享資源安全。具體並行行為由 Spec／design 確認。
- **CODE-06 必要**：日誌採結構化資訊與適當等級；不得以大量無關輸出掩蓋失敗。機密與錯誤資訊處理另依安全規範。
- **CODE-07 必要**：本次變更不得引入編譯警告；有既有警告時說明基線，禁止關閉分析器、NoWarn 或降低門檻以換取綠燈。Directory.Build.props 以 TreatWarningsAsErrors 在建置時強制；修改 Directory.Build.props 或 .editorconfig 屬政策例外。
- **CODE-08 建議**：消除影響本次正確性或維護性的重複邏輯、過深分支與多重責任；提出具體影響，不依個人偏好要求抽象化。

新套件與相依調整需在核准範圍，說明用途及相容性；不得為小功能引入未需要的完整架構框架。
